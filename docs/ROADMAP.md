# Ableton Helper — дорожная карта v2: от «генератора звуков» к полноценному помощнику

Статус на момент составления: работает цепочка чат → Claude → Remote Script → Live 11.3.25.
Есть: создание звуков (47 рецептов, display-значения по реальной калибровке), сэмпловые
инструменты (FreePats CC0 → пресеты Sampler), `adjust_sound` (29 правок), RAG по базе знаний
(help / sound / theory), MIDI-клипы в Session View. Обратная связь пользователя: баян и бас стали
лучше, но нужен «полноценный помощник».

## 3. Принципы (обязательны для всех этапов)

1. **Ничего чужого без спроса.** Объекты, созданные пользователем, меняются только после явного «да» в UI. Создавать новое — можно без вопросов, если это прямо попросили.
2. **Спрашивать, когда выбор существенный.** Неясный жанр/темп/тональность, «заменить или добавить?», куда поставить партию — `ask_user` с 2–4 вариантами; не спрашивать по мелочам (дефолты из профиля и анализа сета).
3. **Live 11 — первый класс, Live 12 — бонус.** Каждая новая команда моста: feature-detect (`hasattr`), фолбэк для Live 11, запись в `get_capabilities`.
4. **Сначала спайк на реальном Live.** Любая новая функция Live API проверяется тестовым скриптом у пользователя до разработки поверх неё (этап 0).
5. **Прозрачность.** Каждое изменение — в журнале действий с «было → стало»; ответ ассистента перечисляет, что изменено.
6. **Тесты.** FakeBridge эмулирует каждую новую команду; сквозной тест через настоящий Remote Script на фейковых объектах Live; ручной чек-лист для реального Live.

## 4. План по этапам

### Этап 0. Проверка API на Live 11.3.25 (спайк, ½ дня)
Цель — снять риски до разработки. Делается командой `abhelper probe` (новая), которая вызывает тестовые команды моста и печатает отчёт.

| Проверка | Как | Нужно для |
|---|---|---|
| `Track.arrangement_clips` (документировано с Live 11.0) | прочитать клипы аранжировки, их `start_time`, `length`, ноты | 1, 2, 4 |
| `Track.duplicate_clip_to_arrangement(clip, time)` | создать временный клип в Session → дублировать на такт 9 → удалить временный | 2 (путь для Live 11) |
| `Track.create_midi_clip(start, length)` в Arrangement | вызвать, если есть (ожидаемо Live 12) | 2 (путь для Live 12) |
| `Track.delete_clip(clip)` для клипов Arrangement | удалить созданный клип | 2, откат |
| Маркеры: `song.cue_points`, `song.set_or_delete_cue()`, `song.current_song_time` | поставить маркер «Verse» на такт 9 | 2 |
| Выделение: `song.view.selected_track`, `song.view.detail_clip`, время выделения в Arrangement | прочитать | F2 |
| `song.root_note` / `song.scale_name` | прочитать/записать | F4 |
| Маршрутизация: `track.available_input_routing_types`, `compressor` sidechain-параметры | прочитать | F6 |
| Метры: `track.output_meter_left/right` | прочитать во время воспроизведения | F6 |

**Готово, когда:** у пользователя отработал `abhelper probe`, отчёт приложен в `docs/calibration/probe-live-11.3.25.json`, каждая строка помечена «работает / нет / фолбэк».

### Этап 1. Диалог и безопасность изменений (U1, U5, F2, F14) — основа для всего остального
**1.1 Реестр владения** (`backend/abhelper/agent/ownership.py`)
- Отмечает дорожки/клипы/устройства, созданные ассистентом (по `track_index` + имени + отпечатку: имя, цвет, устройства; переживает сдвиг индексов).
- Хранится по `conversation_id` + на диске для текущего сета.
- Мост: команда `get_object_ids` — стабильные идентификаторы Live-объектов в пределах сессии (Python-объекты Live сравниваются через `==`; ведём таблицу в Remote Script).

**1.2 Шлюз подтверждений** (`backend/abhelper/agent/guard.py`)
- Каждый мутирующий инструмент классифицирует действие: `create` (новое) / `modify_own` / `modify_foreign` / `destructive`.
- `modify_foreign` и `destructive` → инструмент не выполняется, а возвращает `needs_confirmation` с описанием «что и как изменится».
- Агент обязан показать вопрос; UI рисует карточку с кнопками «Да, меняй» / «Нет» / «Сделай копию»; ответ уходит как сообщение пользователя с токеном подтверждения (`confirm_id`), который снимает блок ровно для этого действия.
- Настройка «уровень доверия»: всегда спрашивать / спрашивать только для чужого (по умолчанию) / не спрашивать.

**1.3 Встречные вопросы** — инструмент `ask_user(question, options[], allow_free_text)`
- Ход агента завершается вопросом; UI показывает варианты чипами.
- Промпт: когда спрашивать (неоднозначность, стоимость ошибки, длинная операция), когда не спрашивать (есть дефолт).

**1.4 Контекст выделения** — инструмент `get_selection` (выделенная дорожка, клип, устройство, диапазон в Arrangement) + промпт: «этот/эту» = выделенное.

**1.5 Журнал и откат** — `action_log` (все изменения с «было → стало»), инструмент `revert_last_request` (обратные операции по журналу; где нельзя — Live `undo` N раз с проверкой).

**Готово, когда:** «переделай бас» на пользовательской дорожке всегда вызывает подтверждение; «откати» возвращает состояние; тесты на все классы действий; ручная проверка в Live.

### Этап 2. Arrangement View (U4)
**2.1 Мост** (Remote Script 0.4.0):
- `get_arrangement` — клипы всех дорожек: дорожка, старт/длина в долях и тактах, имя, цвет, MIDI/аудио; маркеры; длина песни; размер.
- `create_arrangement_clip(track_index, start_bar, length_bars, notes, name, color)` — Live 12: `create_midi_clip`; Live 11: временный слот Session → `duplicate_clip_to_arrangement` → удаление временного клипа (по результатам этапа 0).
- `get_arrangement_clip_notes`, `set_arrangement_clip_notes` (только после подтверждения для чужих), `delete_arrangement_clip`.
- `set_cue(bar, name)`, `set_song_loop(start, length)`, `jump_to(bar)`.
- Проверка пересечений: не класть клип поверх существующего без подтверждения.

**2.2 Агент:**
- Инструменты `write_part(track, section|bars, notes|generator)` и `build_song_structure(genre, sections[])` — создаёт маркеры секций (Intro 8, Verse 16, Chorus 16…) и раскладывает партии по секциям с вариациями.
- Настройка «куда писать по умолчанию»: Arrangement (по запросу пользователя) / Session.
- База знаний `theory/arrangement.md` уже есть — промпт ссылается на неё при построении структуры.

**Готово, когда:** «напиши бас под баян на 16 тактов с 9-го такта» создаёт клип в Arrangement на нужном месте; «сделай структуру куплет-припев» ставит маркеры и партии; пересечения ловятся.

### Этап 3. Сэмплы пользователя (U3, F5, F7)
**3.1 Индекс** (`backend/abhelper/userlib/`): обход папок (User Library, Places из настроек Live, папки из конфига), метаданные (длительность, sample rate, BPM/тональность из имени, loop/one-shot по длительности и началу, громкость/спектральный центроид — numpy + stdlib wave/FLAC), кеш SQLite, инкрементальное обновление. Команда `abhelper samples scan`.
**3.2 Поиск по описанию:** «мягкий кик», «тёплый вокальный чоп в ля минор» — токены имени/папки + признаки (короткий/длинный, яркий/тёмный, тональность) + синонимы RU/EN. Опционально позже: аудио-эмбеддинги (CLAP) как плагин.
**3.3 Загрузка:** в Simpler (one-shot/loop с настройками), в Sampler (мультисэмпл из папки по нотам — переиспользуем генератор `.adv`), в Drum Rack (генератор `.adg`: пэды C1… по ролям, choke для хэтов).
**3.4 Аудио → MIDI:** basic-pitch (опциональная зависимость) → клип в Session/Arrangement.

**Готово, когда:** «собери мне кит из моих сэмплов в стиле лоу-фай» создаёт Drum Rack с 8 подходящими сэмплами; «найди кик помягче» отдаёт 3 варианта с прослушиванием (загрузка по выбору).

### Этап 4. Продюсерский помощник (U2, F4, F6, F8, F10)
- `analyze_project`: инструменты/роли дорожек, тональность (F4), плотность по тактам, пустые частотные зоны (по ролям), отсутствие элементов (нет баса/ударных/хука), длина и структура аранжировки → список «что добавить» с кнопками «сделай».
- Советы по сведению (F6): метры уровней при воспроизведении, перегрузы, моно-бас, сайдчейн.
- Референс (F8), режим обучения (F10).

### Этап 5. Качество звука и память (F1, F3, F9, F11, F13)
- «Сохрани этот звук» → пользовательские рецепты, приоритет в поиске.
- Вариации и humanize (F3).
- Профиль предпочтений и заметки проекта (F9).
- Новые CC0-паки с многослойной velocity (F11).
- Выбор модели по задаче и показ стоимости (F13).

### Этап 6. Платформа (F12, F15)
Голосовой ввод, MCP-режим, сборка установщика для Windows (один `.exe`/скрипт: Python-окружение + Remote Script + ярлык чата).

## 5. Порядок и зависимости

```
Этап 0 (спайк API) ──► Этап 1 (диалог/безопасность) ──► Этап 2 (Arrangement) ──► Этап 4 (анализ/советы)
                                   └──────────────────► Этап 3 (сэмплы)       ──► Этап 5 (качество/память)
Этап 6 — в любой момент после 1.
```
Этап 1 обязателен до 2 и 3: и аранжировка, и работа с сэмплами меняют существующие объекты.

## 6. Как исполнять (оркестрация)
На каждый этап — свои агенты с непересекающимися файлами:
- **Live Bridge** — новые команды Remote Script (Python 3.7, feature-detect, тесты на фейках Live), версия протокола.
- **Agent Core** — инструменты, промпт, шлюз подтверждений, журнал.
- **UX** — карточки подтверждения, чипы вариантов, панель «что добавить», индикатор Arrangement/Session.
- **Domain** (звук/теория/сэмплы) — генераторы партий, индексы, рецепты, база знаний.
Оркестратор: контракт в `docs/PROTOCOL.md` и `docs/INTERFACES.md` до старта, интеграционный тест через настоящий Remote Script, ручной чек-лист для пользователя в конце этапа.
